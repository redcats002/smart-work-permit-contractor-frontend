# PRE-003 — Multi-asset rendering on print pages

**Type:** bug · **Module:** pre-contract / contract print · **Status:** done

## Problem

Both print pages only render the **first asset** (`asset[0]`) of a contract/pre-contract. A
contract can have multiple collateral assets — printing only the first one is incorrect business
behavior.

### Affected code

| File | Line | Current | Correct |
|---|---|---|---|
| `src/pages/contract/pages/print/composables/useInitPrint.ts` | 24 | `asset.value = assetRes.data[0] ?? null` | `assets.value = assetRes.data` |
| `src/pages/contract/pages/pre-contract-print/composables/useInitPreContractPrint.ts` | 31 | `asset: data.preAssets[0] ?? null` | `assets: data.preAssets` |
| `src/pages/contract/components/print/LoanAgreementDocument.vue` | 209 | `asset: IPreAssetList \| null` | `assets: IPreAssetList[]` |
| `src/pages/contract/components/print/LoanAgreementDocument.vue` | 222 | `const asset = computed(...)` | `const assets = computed(...)` |
| `src/pages/contract/pages/print/pages/ContractPrintPage.vue` | 45 | `asset: asset.value` | `assets: assets.value` |

## Tasks

### 1. Update `ILoanAgreementDocument` interface

In `LoanAgreementDocument.vue`, change:

```ts
// before
asset: IPreAssetList | null

// after
assets: IPreAssetList[]
```

### 2. Update `useInitPrint.ts`

- Change return type from `asset: Ref<IContractAssetList | null>` to `assets: Ref<IContractAssetList[]>`
- Change fetch: `assets.value = assetRes.data` (full array, not `[0]`)
- Default: `assets.value = []` instead of `null`

### 3. Update `useInitPreContractPrint.ts`

- Change mapping: `assets: data.preAssets` (full array, not `[0] ?? null`)

### 4. Update `ContractPrintPage.vue`

- Change view-model mapping: `assets: assets.value` (rename from `asset`)

### 5. Update `LoanAgreementDocument.vue` template

Change ข้อ 2 section to loop over all assets:

```html
<template v-for="(asset, index) in assets" :key="asset.id ?? index">
  <!-- render each asset detail -->
</template>
```

Each asset renders its detail according to its type. The formatting logic should use the
utility function from PRE-004 (or inline temporarily if PRE-004 is not yet done).

## Acceptance criteria
