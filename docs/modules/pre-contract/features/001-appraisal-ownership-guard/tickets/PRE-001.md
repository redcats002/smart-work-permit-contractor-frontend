# PRE-001 — Restrict appraisal confirmation to the assigned appraiser

**Type:** feature · **Module:** pre-contract · **Status:** done

## Problem

Any user viewing a pre-contract in `UNDER_EVALUATION` could open the "ยืนยันราคาประเมิน"
modal and submit a confirmed appraisal price, regardless of whether they were the appraiser
assigned to that contract. Nothing in the UI distinguished the assigned `sellMan` from any
other employee who could reach the page.

## Acceptance criteria

- [x] The confirm-appraisal action proceeds only when the current user is the contract's
      `sellMan`, or holds role `SUPER_ADMIN` or `ADMIN`.
- [x] An unauthorized user sees `คุณไม่ใช่พนักงานประเมินของสัญญานี้ ไม่สามารถยืนยันราคาประเมินได้`
      and the modal does not open.
- [x] Roles are compared against `EmployeeRoleEnum`, not string literals.
- [x] Lint and type-check pass on all touched files.

## Out of scope

- Server-side enforcement of the same rule. This ticket delivers the client-side UX guard
  only; the API check is a separate backend concern and was **not** verified.
- Hiding or disabling the button entirely. The button stays visible and explains why the
  action is unavailable — chosen over hiding so the user understands the restriction rather
  than wondering where the action went.
